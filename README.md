# 实习生实战题库 · upio

> 我们不看简历筛人，看你能不能把一件事做到**线上能用**。
> 选一道题，48 小时，把代码提成 PR，**并把它真正部署上线**。
> 最后一条验收标准只有一条：**这东西现在跑在公网上，我们点开就能用。**

## 这是什么

这三道题分别是我们真实业务里三条链路的**缩小版**：内部知识检索（「企业大脑」）、异步任务编排（渲染工作流）、无 API 环境下的消息自动回复（微信侧）。素材全部脱敏合成，仓里自带 mock 服务与评测脚本，你**不需要**我们的任何账号、key 或环境。

每人只做一道。三道题难度相当，选你最有把握**做完并送上线**的。

| 题 | 一句话 | 适合 | 题面 |
|---|---|---|---|
| **E1 迷你企业大脑** | 对约 30 篇内部文档建索引，命令行检索并给出出处 | 喜欢搜索/数据/后端 | [tasks/E1-mini-brain](tasks/E1-mini-brain/README.md) |
| **E2 工作流自动化** | 收 webhook → 提交异步渲染任务 → 轮询 → 通知；n8n 或任意语言 | 喜欢自动化/集成/后端 | [tasks/E2-workflow-automation](tasks/E2-workflow-automation/README.md) |
| **E3 微信消息自动回复** | 用 UI 自动化驱动一个仿微信网页版，读消息、分类、回复 | 喜欢前端自动化/爬虫/RPA | [tasks/E3-wechat-autoreply](tasks/E3-wechat-autoreply/README.md) |

## 验收的终点是上线

我们招的人要做的事，终点从来不是「本地跑通了」。所以这里的验收分三层，**最后一层是硬门槛**：

| 层 | 怎么验 | 不过会怎样 |
|---|---|---|
| ① 本地跑通 | 你自己 `./scripts/eval-local.sh` | —— |
| ② 自动评测通过 | 提 PR 后 CI 跑公开集；面试官评论 `/eval` 跑隐藏集 | 分数进 rubric；不过 check 也会红 |
| ③ **真实部署上线** | 你给出公网地址，CI 自动探活；面试官**亲自打开用一遍** | **一票否决**：没有可用的线上地址，自动评测分数再高也不进走读 |

**你要交的**：提交目录里放一个 `DEPLOY.md`，里面**第一条 `URL:` 行**写你的线上地址（建议就放在文件开头）：

```
URL: https://你的线上地址
```

单独成行的裸地址最保险——表格里、代码块里的地址我们读不到。

- 这个地址必须**公网可达**（不能是 `localhost` / 内网 IP / 需要 VPN 才能到的地址）。填一个 `GET` 就能返回 2xx/3xx 的地址——比如 E2 直接填 `/healthz` 那条路径，别填一个按题面本来就该 404 的根路径
- **从你提 PR 起到我们评审结束（PR 被关闭并打标签那一刻）保持在线**
- 冷启动慢没关系（免费实例休眠很正常），探活**最多等 5 分钟**并反复重试；**但它必须能自己醒过来**
- CI 的探活只证明「这个地址活着」；**能不能用，是面试官亲自打开来看的**
- 各题「上线」具体长什么样、面试官会做哪个动作来验，见各自题面的「上线要求」一节
- 自己先验一遍：`./scripts/check-deploy.sh submissions/<题号>/<用户名>/DEPLOY.md`——CI 跑的就是这一条，判定完全一致

**关于成本**：**我们不发放账号、也不报销费用**，请只用免费额度或你自己已有的资源，不要为这道题付费。免费额度够不够用、会不会休眠、要怎么权衡，本身就是这道题的一部分——把你的取舍写进 `DEPLOY.md`。上线用到的任何 key 只放在平台的环境变量里，**不许提交进仓库**。

## 怎么做

1. **领题**：在对应题目的 issue 下评论一句「领题」（issue 列表见 [Issues](../../issues)），让我们知道你在做哪一道。
2. **Fork 本仓**，建分支 `task/<题号>-<你的 GitHub 用户名>`，例如 `task/E2-zhangsan`。
3. 代码放在 `submissions/<题号>/<你的 GitHub 用户名>/`，目录名全小写，必须与你的 GitHub 用户名一致。目录里**必须有** `Dockerfile`、`README.md`、`DEPLOY.md`。详见 [CONTRIBUTING.md](CONTRIBUTING.md)。
4. 本地跑评测：`./scripts/eval-local.sh <题号> <用户名>`。
5. **部署上线**，把地址写进 `DEPLOY.md` 的 `URL:` 那一行，并用 `./scripts/check-deploy.sh submissions/<题号>/<用户名>/DEPLOY.md` 自查。
6. 提 PR 到本仓 `main`，按 PR 模板填写。CI 会自动跑公开评测 **+ 探活你的线上地址**，两项都绿才是绿。
7. 我们收到后会在 PR 上评论 `/eval`，触发隐藏用例评测、一轮自动 review 与一次上线复验，然后人工看，**并亲自打开你的线上地址用一遍**。
8. 我们会留 1–3 条修改意见，请在 **48 小时内**改一轮（这个窗口和做题的 48 小时是两回事）。代码改完记得**同步更新线上**——我们复验的是线上那一份。
9. 通过的话约 30 分钟通话，请你讲讲你的代码和你的部署。

**截止时间**：从你收到邀请那一刻算起 **48 小时**，代码与上线都在这 48 小时内完成。交得早不加分——我们看的是完成度和过程。

## 规则

- **可以用 AI 工具**（Claude Code、Cursor、ChatGPT……我们自己天天用）。但通话时你要能解释每一个决定。解释不了的代码，等于没写。
- 自动评测环境**没有任何 LLM key、没有外网账号**。你的方案必须在没有 key 的情况下也能跑；有 key 时更好是加分项。
- **没有线上地址 = 验收不通过。** 「本地能跑，就是没时间部署」在这里不成立，这一条就是我们要筛的东西。
- 一个 PR 只改自己的目录。改了别的路径，CI 直接红。
- PR **不会被合并**——这是评估通道，不是贡献通道。评审完成后我们会尽快关闭并打标签，那时你就可以把线上实例关掉。
- 语料与 mock 来自真实生产环境的脱敏版，**不保证干净**。请按你对待生产环境的方式对待它们。
- 请不要在提交里放任何真实的 key、token、手机号。

## 怎么评

评分标准公开：[review/RUBRIC.md](review/RUBRIC.md)。五个维度：验收（30）、解决问题（25）、工程质量（15）、沟通与过程（15）、迭代响应（15）；**外加「已上线且可用」这个一票否决的门槛**。

其中「解决问题」这一项，我们看的是：题目没明说、但真实环境里一定会遇到的问题，你有没有发现、怎么处理、在 README 里怎么写的。**发现了但选择不处理并写明原因，也算发现。**

上线之后才会暴露的那批问题——冷启动、端口绑定、环境变量、日志去哪看、挂了怎么恢复——同样算在这一项里。写进 `DEPLOY.md`。

## FAQ

**Q：可以两道题都做吗？** 不用。做一道做透。

**Q：可以用什么语言？** 任意。自动评测只认容器接口。

**Q：我没有服务器，也没有信用卡，怎么部署？** 容器托管平台、PaaS、Serverless、学生机、你自己的旧电脑 + 内网穿透都行，只要地址公网能打开。选哪个我们不限定，也不推荐——**选型和踩坑本身就是这道题的一部分**，把你怎么选的、免费额度够不够，写进 `DEPLOY.md`。

**Q：免费实例会休眠，第一次打开要等几十秒，会被判死吗？** 不会。探活最多等 5 分钟、反复重试。但如果它睡过去就醒不来、或者要你手动点一下才活，那算不可用。

**Q：E3 要一个浏览器容器长跑，免费额度扛不住怎么办？** 在 `DEPLOY.md` 里写清楚它能在什么条件下跑（比如只在某个时段起、或需要我们提前说一声再拉起），并写明怎么拉起。我们按你写的来验；写清楚不扣分，什么都不写、我们打开是死的才扣。

**Q：E1 是个 CLI，怎么「上线」？** 见 [E1 题面的「上线要求」](tasks/E1-mini-brain/README.md)。简单说：容器的 CLI 接口不变（评测走它），另外包一层公网能访问的入口，让我们能自己提问、自己看到出处。

**Q：上线的那份和提交的代码可以不一样吗？** 不可以。线上跑的必须是这个提交目录里的代码。允许的差异只有配置（env、端口、key）。

**Q：我的线上实例在评审期间挂了怎么办？** 尽快恢复并在 PR 里说一句。判定以**我们复验那一刻能不能打开**为准，所以别赌。`DEPLOY.md` 里写清楚你怎么发现它挂了、怎么恢复——这部分算在「解决问题」里。

**Q：什么时候可以下线？** 我们关闭 PR 并打标签之后。

**Q：mock 或评测脚本有 bug 怎么办？** 提 issue 或直接在 PR 里说明。发现评测脚本的 bug 并给出复现步骤，会在「解决问题」里加分。

**Q：我做到一半时间到了怎么办？** 交。写清楚做到哪、没做什么、为什么。一个诚实的半成品比一个看不懂的全成品有价值——**但半成品也要上线**，我们要看的是你把手上这一版送上去的能力。

**Q：有问题问谁？** 开一个 [issue](../../issues/new/choose)。我们工作日 24 小时内回。
